Tokenization 
    - the process of breaking down text into smaller units called tokens.
    - tokens are mapped to an embedding vector
    - there are mutliple tokenization methods
    
        "Hello, how are you doing today?"
        → ["Hello", ",", "how", "are", "you", "do", "ing", "today", "?"]
        → [15496, 11, 634, 389, 345, 1103, 356, 2375, 30]
        15496 → vector [0.12, -0.37, 0.44, ...]


        Tokens are not universal. Each model (GPT, BERT, LLaMA, etc.) has its own tokenizer and vocabulary.
            - actual vectors (like [0.12, -0.37, 0.44, …]) are learned during training.
        chunks depend on the rules learned during that model’s training.
        Each token ID corresponds to a vector (embedding).
        
        - embedding matrix
            - Inside every language model, there’s a huge embedding matrix.
            - a giant lookup table.
            vocabulary size 
                = how many tokens the tokenizer knows (eg, 50k).
            embedding dimensions
                = model’s hidden size (e.g., 768, 1024, 12288).
            Example for BERT-base:
                - vocab_size ≈ 30,000
                - embedding_dim = 768
                - Matrix size = 30,000 × 768 ≈ 23 million parameters
                (layers can also make matrix bigger, idk how it works)
                
            - yes, there’s a limited number of tokens in each model, fixed at training time
                
        
        
Encoders & Decoders

Encoder: 
    - Converts raw input (text, image, audio) into embeddings (dense vectors).
    - must use the exact same encoding algorithm during inference. ... Consistency
    - encoding algorithm is not “baked into” the model, 
        but the model depends on it.
    - bundling: 
        - frameworks package the model together with the tokenizer/encoder.
            - eg Hugging Face Transformers or TensorFlow Hub
        - This ensures that anyone loading the model automatica
        or 
        - The developer ships a preprocessing function along with the model.
        or
        ONNX (Open Neural Network Exchange)
            - so models can be shared across frameworks and platforms
            - allows models trained in one framework to run in another
Decoder: 
    - Takes embeddings and generates outputs (text, image, audio).
    - usually part of the model’s parameters 
    - Decoder is learned by the model itself
    - Decoder relies on internal learned parameters to generate outputs, 
        - so no special "same" algorithm is needed 
    fun fact
        - Decoder's output in a raw or intermediate numerical form
        Typical Model Outputs
            Text models: Output a sequence of token IDs or probability distributions over a vocabulary.
            Image models: Output a tensor of pixel values (e.g., a 3D array for RGB).
            Audio models: Output a waveform array or spectrogram values.

    
    
Embedding
    - how language models “see” text.
    - a vector so the model can work with the token
    - vector/embedding represents a token
    "cat" → 3542 → [0.12, -0.88, 0.33, 0.41, -0.07]1
    
    Embedding space
        - a huge 3D map (except instead of 3 dimensions, it might be 768, 1024, or 12,288 dimensions).
        
Positional Encoding
    = extra numbers added to token embeddings to mark their position.
    - used in transformer models 
        - eg BERT, GPT
    - shows order of tokens in a sequence.
    
    - So the model knows:
        "I love cats" ≠ "cats love I".
    
Attention 
    - is a way for a model to focus on the most relevant parts of the input.
        - Each input element (like a word) gets a weight showing its importance.
        - The model uses these weights to decide what to emphasize when making predictions.
        - important in transformers
            - can "look at" other parts to understand context.
    - It’s essentially dynamic weighting of input features based on relevance.
    - how each word (or token) in a sequence is important to other words via a weight

AWS OpenSearch 
    - a search & analytics service, built on Apache Lucene
    - Vectorstore - but later Amazon allowed to act as a vectorstore
        - (does not comput embedding, just stores)
            - unlike its native text/keyword searching via Lucene (can compute & store & search)
    Lucene features (native)
        - Keyword / exact match search
        - Full-text search (tokenization, stemming, stopwords)
        - Boolean queries (AND, OR, NOT)
    Embedding / vector search (AI/ML)
        - OpenSearch stores and searches vectors (dense_vector)
        - you must generate embeddings externally using ML models
        - Can combine with Lucene queries (hybrid search)
    Traditional search
        - feed text → OpenSearch handles indexing & search via Lucene
    Vector search
        - feed text → external ML model → generate embedding → store in OpenSearch → query with vector
    
    Lucene = built-in, classic search, no ML needed
    Embeddings = external ML required, OpenSearch handles storage & nearest-neighbor retrieval

    - Inference pipeline is for real-time inference with multiple steps chained.
    - chain models and data processing into a single endpoint.
    - You build a sequence of containers (processing steps or models).
    - requests are ran through the pipeline:
        1. Preprocessing (eg., data cleaning, feature extraction, tokenization).
        2. Model(s) (one or more trained models that generate predictions).
        3. Postprocessing (e.g.,  probabilities to labels, formatting output).

    Predicted label - The value the model predicts for the label.
    Dataset - A collection of samples.
    Bias - Unequal behavior in the data or model predictions across different groups (e.g., age, income).
    Bias metric - A number that shows the level of potential bias.
    Bias report - A set of bias metrics for a dataset or a dataset and model.
    Positive label values - Label values that are favorable for a group.
    Negative label values - Label values that are unfavorable for a group.
    Group variable - A categorical column used to form subgroups for measuring bias in Conditional Demographic Disparity (CDD).
    Facet - A feature used to measure bias.
    Facet value - The specific value of a facet that might be favored or disfavored.
    Predicted probability - The model’s predicted chance of a sample having a positive or negative outcome.

NOTE
    Confusion Matrix
        - shows how well the model's predictions match the actual labels.
            - eg) False Positive (bad), True Positive (good)
        - in classification tasks 
        
    Accuracy: How many predictions (both positive and negative) are correct.
    Precision: Of all predicted positives, how many are actually positive.
    F1 score: is a single number that shows how good a model is at finding the positive cases without making too many mistakes.
    
    Disease detection:
        Positive = has disease
        Negative = healthy
        If the model predicts everyone healthy:
            Accuracy might be high (most people are healthy)
            But it misses all sick people → dangerous
    
    
    Accuracy is used when the True Positives and True negatives are more important
    F1-score is used when the False Negatives and False Positives are more important
    
    | Metric    | What it measures                            | When it matters most                                                         |
    | ----------| ------------------------------------------- | ---------------------------------------------------------------------------- |
    | Accuracy  | Overall correctness (all predictions)       | When classes are balanced and all errors matter equally                      |
    | Precision | Correctness of positive predictions only    | When false positives are costly                                              |
    | F1 Score  | Balance of precision and recall (positives) | When you care about both catching positives **and** avoiding false positives |

Ranking metrics 
    - for recommendation systems.
    - place relevant items at the top of the list.
    
    Types
        1. binary relevance based metrics
            - A item is good or bad (binary)
        2. utility based metrics
            - A item is a measurement of good or bad

    Mean Reciprocal Rank (MRR)
        - Simple, fast and easy
        - cares only about where the first relevant result shows up.
    Mean Average Precision (MAP)
        – looks at all relevant results, assuming each is equally important.
        
    Normalized Discounted Cumulative Gain (NDCG)
        - looks at all results and also how relevant each one is, giving more weight to the top of the list.
        - cares about all items, their order, and how relevant they are.
        - search engines and recommendation systems 
        - complex, slower, hard

NLP Metrics
    Perplexity: 
        - Measures how well a language model predicts text; lower is better.
    BLEU: 
        - Compares generated text to references using overlapping n-grams; higher is better.
        - Bilingual Evaluation Understudy
    METEOR: 
        - Evaluates similarity considering synonyms, stemming, and word order; higher is better.
        - Metric for Evaluation of Translation with Explicit Oddering (METEOR)
    ROUGE: 
        - Focuses on recall of overlapping units (like n-grams or sentences) 
            between generated and reference text; higher is better.
            
Deep Learning Metrics
    - Inception Score (IS):
        - Evaluates how realistic and diverse generated images are. 
        - Uses a pretrained classifier to check if images look like clear objects 
            and if outputs cover many categories.
        👉 IS = quality + diversity of individual images.
    - Fréchet Inception Distance (FID):
        - Measures how close the distribution of generated images is to real ones. 
        - Compares feature representations of real vs. fake images. Lower FID = more realistic and similar to real data.
        👉 FID = similarity between generated set and real set.
